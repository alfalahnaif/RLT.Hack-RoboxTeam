# OKPD2 resolver benchmark v1.0.0

Measures **category resolution only**: free text → official OKPD2 code, or an explicit `CATEGORY_AMBIGUOUS` /
`CATEGORY_UNCERTAIN`. It does not measure supplier ranking. The supplier-ranking replay benchmark
([`../replay/`](../replay/)) and its sealed HOLDOUT are not used or touched.

`cases.json` is generated by `python -m app.search.category_benchmark generate` (seed `20261002`, deterministic)
from the checked-in index (`data/seed/okpd2_category_index.json`), the canonical database (read-only) and
[`curated_cases.json`](curated_cases.json).

| Kind | Source of the label | Expected |
|---|---|---|
| `exact_title` | an official title whose normalized form and lemma sequence are unique in the taxonomy | that code, `RESOLVED` |
| `number_variant` | the same kind of title with every word of its head phrase switched singular↔plural (adjectives agree) | that code |
| `case_variant` | the same, inflected to genitive or dative (`перчаток резиновых`) | that code |
| `one_word_distinctive` | a lemma whose titles form a single ancestor/descendant line (≤ 4 codes), queried in another word form | the deepest code of the line |
| `one_word_ambiguous` | a noun found in ≥ 4 unrelated lines and not itself a title | `CATEGORY_AMBIGUOUS` |
| `procurement_description` | an item name published **before 2025-07-01** (HOLDOUT lots also excluded by id) coded the same way in ≥ 95 % and ≥ 3 of its occurrences | that observed code |
| `unknown` | generated pseudo-words absent from the taxonomy | `CATEGORY_UNCERTAIN` |
| curated (`curated: true`) | acceptance cases of the V4 task and hand-checked variants | as written |

`split` (dev / test) is a hash of the case id. Decision thresholds are tuned on **dev only**; **test** is reported and never tuned on.

Known limitations:

- Inflected variants are generated with the same morphology library the resolver uses (pymorphy3). They test consistency,
  not independent linguistic coverage, so the hand-written curated cases matter more than their count suggests.
- Description labels are customer-assigned codes, so they are noisy. The historical phrase channel of the index is built from the
  whole dataset, so descriptions are partly in-sample for that channel.
- `one_word_ambiguous` is defined from the taxonomy structure. Some of these words could reasonably resolve to an exact
  one-word title, and those words are excluded.

## Architecture

INN → official EGRUL legal identity + extract (`FnsEgrulRegistry`: identity, status, OGRN/KPP, registered address, primary OKVED) → optional secondary registry (`CheckoRegistryMirror` behind a per-batch circuit breaker: corroboration, website hint; never required) → candidate website (`WebsiteDiscoveryProvider`) → website identity verification (`WebsiteVerifier`) → first-party contacts (`ContactExtractor`) → role evidence (`RoleEvidenceProvider`) → freshness (`app/enrichment/freshness.py`) → persistence (migration 0005: `supplier_enrichment_profile`, `supplier_contact`, `supplier_enrichment_evidence`, `supplier_role_evidence`, `supplier_enrichment_attempt`). Pipeline = `app/enrichment/pipeline.py` (pure, injected providers); API = `GET /api/v1/suppliers/{inn}/profile` (read-only, never live) and `POST /api/v1/suppliers/{inn}/enrich[?refresh=true]` (cache-first, bounded, synchronous).

## Provider sources actually used

| Provider | Source | Used for | Not used for |
|---|---|---|---|
| FNS_EGRUL (primary, required) | egrul.nalog.ru official search | legal name, short name, OGRN, KPP, region, registration date, active/ceased | director names (ignored) |
| FNS_EGRUL_EXTRACT (sub-step) | official EGRUL/EGRIP extract (PDF) from egrul.nalog.ru | registered address (legal entities only), primary OKVED; only when the extract's INN matches | anything personal |
| CHECKO_REGISTRY_MIRROR (optional) | checko.ru (FNS-derived registry mirror) | website hint; fills address / OKVED gaps only when the official extract failed and INN + OGRN match | its phones / e-mails; never required — rate limiting opens a circuit breaker for the rest of the batch |
| FIRST_PARTY_WEBSITE | the company's own site (≤ 6 same-host pages) | identity verification, general phone / e-mail, content currency, first-party role claims | anything when identity is not confirmed |

Official website = INN or OGRN published on the site, or exact legal name + registered street address (street + house number). Exact name + locality only = MEDIUM (stored as candidate, not official). Roles: OKVED → INFERRED only; first-party production / official-distribution wording → UNDER_REVIEW; the pipeline never writes VERIFIED (DB check). Individual entrepreneurs: identity only (their contacts are personal data).

## P5-001A.1 summary (added manually — numbers are copied from this report and `p5_001a1_egrul_only_sample.*`)

**What changed:** official EGRUL is now the primary and only required identity source. The FNS search gives legal name, short name,
OGRN, KPP, status, registration date and region. The official extract (PDF, same service) gives the registered address and the
primary OKVED. checko.ru is an optional secondary provider (website hint, gap filling, corroboration) behind a circuit breaker that
opens after 2 consecutive rate-limited answers and stays open for the rest of the batch.

|---|---:|---:|
| EGRUL legal identity | 5 / 5 (100 %) | 30 / 30 (100 %) |
| EGRUL registered address | 5 / 5 (100 %) | 26 / 30 (86.7 %) = 26 / 26 legal entities; entrepreneurs have no published address |
| EGRUL primary OKVED | 5 / 5 (100 %) | 30 / 30 (100 %) |
| Official website verified | 0 / 5 | 0 / 30 |
| Phone / e-mail | 0 / 5 | 0 / 30 |
| Role evidence (OKVED-inferred only) | 3 / 5 | 15 / 30 (50 %) |
| COMPLETE / PARTIAL / FAILED | 0 / 5 / 0 | 0 / 30 / 0 |
| Median runtime per supplier | 4.3 s | 4.8 s (p90 6.9 s) |

**checko.ru availability (reported separately, not an enrichment failure):** still rate-limiting. 2 suppliers got RATE_LIMITED
(after one bounded backoff), then the breaker opened and the remaining 28 calls were skipped. No supplier failed because of it.

**Comparison with run 1 (checko as a core dependency, before this change):** address went from 18 / 30 (60 %, only where checko
answered) to 26 / 30 (all legal entities, official source). OKVED went from mirror-dependent to 30 / 30 official. FAILED stays 0.

**Known gap (the next limit to address, not done here):** website discovery has no source other than the checko hint, so verified
website, phone and e-mail coverage is 0 while checko is blocked (run 1 reached 4 / 30 websites with checko partly available).
EGRUL does not publish websites. Any new discovery source must keep the existing rule: a site is official only when its identity
is proven on the site.

**Extract identity check (found during the sample):** some extracts have no INN in the header, and the first "ИНН" row is a
founder's personal INN. The extract is accepted only on the header INN, the "ИНН юридического лица" row, or the header OGRN
matching the search record. Person rows are never read.

**Database:** `supplier_radar_p5` only (0005 re-applied after the RATE_LIMITED outcome was added). `supplier_radar` stays at
`0004_semantic`. The P4/demo API is unchanged.

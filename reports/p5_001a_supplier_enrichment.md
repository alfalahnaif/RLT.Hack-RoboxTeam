## Architecture

INN → legal identity (`CompanyRegistryProvider`) → candidate website (`WebsiteDiscoveryProvider`) → website identity verification (`WebsiteVerifier`) → first-party contacts (`ContactExtractor`) → role evidence (`RoleEvidenceProvider`) → freshness (`app/enrichment/freshness.py`) → persistence (migration 0005: `supplier_enrichment_profile`, `supplier_contact`, `supplier_enrichment_evidence`, `supplier_role_evidence`, `supplier_enrichment_attempt`). Pipeline = `app/enrichment/pipeline.py` (pure, injected providers); API = `GET /api/v1/suppliers/{inn}/profile` (read-only, never live) and `POST /api/v1/suppliers/{inn}/enrich[?refresh=true]` (cache-first, bounded, synchronous).

## Provider sources actually used

| Provider | Source | Used for | Not used for |
|---|---|---|---|
| FNS_EGRUL | egrul.nalog.ru (official FNS search) | legal name, short name, OGRN, KPP, region, registration date, active/ceased | director names (ignored) |
| CHECKO_REGISTRY_MIRROR | checko.ru (FNS-derived registry mirror; accepted in P4-005C) | registered address, primary OKVED, website hint; only when INN + OGRN match | its phones / e-mails (aggregated, possibly personal / stale) |
| FIRST_PARTY_WEBSITE | the company's own site (≤ 6 same-host pages) | identity verification, general phone / e-mail, content currency, first-party role claims | anything when identity is not confirmed |

Official website = INN or OGRN published on the site, or exact legal name + registered street address (street + house number). Exact name + locality only = MEDIUM (stored as candidate, not official). Roles: OKVED → INFERRED only; first-party production / official-distribution wording → UNDER_REVIEW; the pipeline never writes VERIFIED (DB check). Individual entrepreneurs: identity only (their contacts are personal data).

## Run log and limitations (added manually — not regenerated by `enrichment report`)

- **Database:** pilot ran on `supplier_radar_p5`, a reduced copy of the main database (supplier, supplier_history, procurement_lot,
  procurement_item; row counts identical to `supplier_radar`; no raw tables, embeddings or text-search indexes). Migration 0005 is
  applied there only; the main database `supplier_radar` stays at `0004_semantic`. The P4/demo API is unchanged.
- **Run 1 (this report, 2026-10-02 06:43 UTC):** the measurement. CHECKO_REGISTRY_MIRROR answered HTTP 429 for 12 / 30 suppliers, so
  those suppliers lack the mirror fields (registered address, primary OKVED, website hint). Address, website and role coverage are
  therefore lower bounds; legal identity (FNS EGRUL) is 30 / 30.
- **Run 2 (`--refresh`, `p5_001a_supplier_enrichment_run2_rate_limited.*`):** checko.ru answered 429 to every request, even after
  backing off once. All 30 profiles degraded to legal identity only. This is a source-availability incident, not a pipeline result.
  It also overwrote the run-1 snapshots in `supplier_radar_p5`. The fix is applied after run 2 and covered by tests.
- **Fixes made after the pilot (all tests pass, 424):** a 429/503 response is waited out once (Retry-After, at most 30 s), then reported;
  checko.ru gets a 3 s per-host interval; an outage of the mirror or the website gives a PARTIAL with `retryable=true`
  (`REGISTRY_MIRROR_UNAVAILABLE`), retried after 24 h rather than kept for the 30-day profile TTL; a degraded refresh never replaces a stored
  snapshot that has more contacts (`LAST_REFRESH_DEGRADED`).
- **Operational finding:** checko.ru does not tolerate batch use at ~1 request/s from one IP. Batch enrichment must stay small and slow
  for this mirror, or registered address / OKVED must come from an official FNS source (for example the EGRUL extract) instead. This is
  not implemented.
- **Not yet done:** re-run of the pilot after the checko block lifts (same 30 INNs, deterministic selection, `--refresh`).
- **Superseded by P5-001A.1** (`p5_001a1_pilot.md`, `p5_001a1_egrul_only_sample.md`): official EGRUL extract is the primary source of
  address / OKVED; checko.ru is optional behind a circuit breaker; field-level weak-refresh protection.
